# Task Changelog

## 2026-10-15, A capability name routes by its owner (dotted-instance-names)

`Registry::route` recovers the tool half of a qualified capability name from the owner the routing map returned for that exact key, instead of splitting the name on its first dot, so an instance registered under a name that itself carries a dot now routes every capability it declares. The map was always keyed on `<instance>.<tool>`, so the owner was unambiguous; the first-dot split read "metis.echo.tool.echo" as the instance "metis" plus the tool "echo.tool.echo" and answered `Unknown` for a route the map had already resolved. The undotted case is unchanged, a dotted name and its undotted neighbour keep separate namespaces, and a registry test asserts `route`, `gate`, `validate_request` and `call` all answer a dotted name. Found by `async-initialisation`'s verifier, which had worked around the case with a dotless bundle name; fixed by the orchestrating parent at the operator's instruction, with the full CI gate green on the landing branch.

## 2026-10-15, One asynchronous load entry that initialises and registers (async-initialisation)

A bundle path now becomes a registered, serving plugin in one call. `load_bundle` takes the host first and composes verification, extraction, manifest reading and library selection, the manifest's ABI demand, the library mapping through the landed table rules, the plugin's asynchronous initialisation awaited to completion, the capability cross-check and registration, answering nine typed refusals that `startup-policy` can classify without re-deriving them. The host parameter is what lets a sink be set before a load and observed after one, and it is the only way to read the drop-then-destroy ordering when initialisation fails, which is now asserted through the ledger. `Serving` carries the instance name, the instance, the registered capabilities and the registry the load built; a plugin whose configuration it cannot read and a plugin that fails its own setup stay distinguishable classes. The configuration and the host context travel as `serde_json::Value` and the initialisation body is written by hand, since the plugin-side value types sit behind the authoring feature the runtime keeps off. Residual: a manifest name carrying a dot does not route, `LoadError::Registration` is unreachable with the in-tree fixture, and the capability cross-check compares names only.

## 2026-10-15, The manifest is validated and the host library is mapped (manifest-and-library)

A verified, extracted bundle now becomes a mapped library with a validated table. `Manifest::parse` reads the TOML an author writes, with its identity, version, ABI major and minimum minor, per-target library paths, capability list with inline request and response schemas, and configuration schema; the fields are private and `parse` is the only constructor, so a `Manifest` is proof the text was the format. `Manifest::read` adds the existence test and compares the declared name against the bundle chain's leaf common name, `Manifest::select_library` picks this host's library without touching another target's declaration, and `Loaded::open` decides the manifest's ABI demand before it maps anything, delegating to the landed table rules. The refusals are six typed errors, and contract 17.9 documents the field table, a complete hand-written example, the check order and the refusal list, with a test that parses the contract's own example so the documentation and the reader cannot drift. Residual: `select_library` resolves a declared path without shape-checking it, so a signed manifest could name a path outside the staging root, which is deferred hardening rather than an escalation. Dependency: `toml` 0.9 with default features off, six crates added and none with a compiling build script.

## 2026-10-15, The C layout assertions compile under MSVC (c-static-assert-msvc)

The plugin contract's C translation unit no longer needs a C11 flag, so `plugin-runtime` and the daemon can be compiled for the Windows target. Every `_Static_assert(condition, "message")` became `METIS_C_LAYOUT_ASSERT(condition, name)`, a `char` array typedef sized `condition ? 1 : -1`, and every `_Alignof(T)` became `__alignof(T)`, which is valid from C89 on and still a hard error in gcc, clang and `cl.exe` when the condition is false. `build.rs` sets warnings-as-errors only under an msvc target environment and stopped passing `-Wall`/`-Wextra` through `flag_if_supported`, where they reached `cl.exe` as its all-warnings level. `scripts/check-c-layout-asserts.sh` is the new pinned check, testing.md command 8 and a CI step: it compiles the unit under gcc and clang in C11 and in strict C89 with warnings denied, and requires a deliberately broken copy to fail in every mode, refusing to run when its substitution did not apply. The `windows` CI job now compiles `-p api-contracts -p daemon --all-targets`, and the bug record is archived as fixed. Residual: no `cl.exe` exists on this host, so the exact MSVC invocation and the widened job are proved by that job's first run.

## 2026-10-15, Asynchronous initialisation in the plugin table (abi-initialisation-entry)

The plugin table's slot 0 is `init_plugin` and no counters entry exists anywhere. Initialisation takes one host-owned payload carrying the configuration and the host context, answers with the instance plus a future, and the host drops the future and then destroys the instance when that future does not resolve `Ok`; a configuration the plugin cannot read is `invalid_argument`, and every other terminal status is the plugin's own defect. `METIS_ABI_MINOR` moves to 2 while the major and `metis_plugin_entry_v1` stay, the table stays eight entries at 80 bytes, and the contract text, the generated header, the slot constants, the layout definitions and the C static asserts moved in the same commit. The Rust fixture and the C plugin both implement the entry and refuse a mismatched configuration, and the ABI harness hand-drives it, now at 82 checks with the waker obligation from the previous ticket closed. The authoring `Plugin` trait broke deliberately (`init` in, `Default` and `started` out, `stopped` kept), which the `metis-plugin-sdk` effort inherits. Residual: the runtime seam has no test for an initialisation that never resolves `Ok`, which `async-initialisation` owns.

## 2026-10-15, Bundle extraction under the archive rules (bundle-extraction)

A verified bundle now becomes a staged directory or a typed refusal. `bundle::extract` walks the archive, validates every entry against the rules it records, stages the root manifest and this host's target directory only, and returns a `StagedBundle` that owns the staging directory, creates files `0600` and directories `0700`, and removes everything when it is dropped or refused. The rules are eight refusals, three limits (256 entries, 64 MiB per entry, 256 MiB declared total) and a strict declared-mode rule of `0600`, so a producer that leaves the `zip` writer's `0o644` default is refused; symlinks, hardlinks, directories, absolute names, `..` names and unreadable entries are refused, and every entry is validated even when its target is not this host's. The archive reader is `zip` 9 with default features off and only the pure-Rust deflate backend, adding six crates with `crc32fast` the only build script and compiling nothing. 28 tests build hostile archives in the test and patch declared sizes byte by byte in the central directory. Residual: a missing root manifest is deliberately not refused here, because `manifest-and-library` owns it, and `StagedBundle::manifest_path()` can name a file that is not there.

## 2026-10-14, Bundle container verification (bundle-verification)

A plugin bundle is now a verifiable artifact rather than an opaque file. `plugin_runtime::bundle` reads a 40-byte big-endian container header, verifies an X.509 over Ed25519 chain against a `TrustStore` the caller supplies, verifies the payload signature over the domain tag, the header, the chain and the archive with the signature bytes deleted, and answers one typed `BundleError` per refusal rule, including the chain profile, the recomputed key ids and the revocation list. A committed 894-byte vector and an altered copy are tested at byte level and rebuilt from a second implementation of the layout on every run, so a moved offset fails the suite. The trusted parse path adds 19 crates, all pure Rust with no C build step, and the contract documents the container, the domain tag bytes `METIS-PLUGIN-BUNDLE-PAYLOAD`, the anchor-is-last-chain-link rule, the key id rule and the refusal split between trust failures and unreadable containers. Residual: extraction, the manifest and the loader are the next tickets, and the ABI harness still owes the waker release the previous ticket's contract now requires.

## 2026-10-14, Waker lifecycle defects in the plugin host (waker-lifecycle-fix)

The three defects the ABI hazard prototype measured are fixed. The host releases the one owning waker reference it hands a poll as soon as that poll returns, `CallState` carries the request id so `Host::wakes_after_drop()` names the call a late wake belongs to, and a `MetisWaker` carries a host-side token so a second wake on one consumed clone is refused instead of over-releasing the call state. `Host::waker_counts()`'s first element changed meaning to every owning reference the host handed out, `docs/plugin-contract.md` section 8 and section 11 rule 4 now say the late wake is a counted violation that names its request id, and the ABI is unchanged, so the fix needed no minor bump. Residual: the ABI harness, the second host implementation, does not yet release its poll's reference, which `abi-initialisation-entry` owns.

## 2026-10-14, Windows named pipe transport (windows-named-pipe)

The Windows half of the local transport exists and the effort's last ticket is in. `PipeName` owns the platform default `\\.\pipe\metis-daemon` and refuses any `METIS_ENDPOINT` override that leaves the local pipe form, `pipe_descriptor_sddl` builds the `D:P(D;;GA;;;NU)(A;;GA;;;<daemon-user-SID>)(A;;GA;;;SY)` descriptor from the daemon's own token, and `serve_pipe`/`serve_pipe_service` accept one byte-mode duplex instance at a time with `first_pipe_instance` and `reject_remote_clients`, handing every accepted pipe to the same `serve_connection` the Unix and TCP front-ends use; `pipe_transport` is the connector. A new `windows` CI job on `windows-latest` compiles the path for the Windows target and runs nothing, so the pipe is proven by construction, by compilation and by the platform-independent rules tested on Linux: it has never executed anywhere, and `docs/testing.md` records the seven gaps with the check that closes each, from the descriptor read-back to the other-account and remote attempts. `-p client` was measured to compile for the Windows target too, so the missing client constructor is a scope decision rather than an impossibility.

## 2026-10-14, Reverse-proxy mode and the plaintext warning (reverse-proxy-mode)

The deployment shape ADR 0004 chose is implemented: the daemon stays plaintext and a reverse proxy terminates TLS in front of it. `METIS_TRUSTED_PROXIES` names exact proxy addresses, `X-Forwarded-For` and `X-Forwarded-Proto` are read only when the peer is one of them and never from an unnamed peer, and the TCP front-end now stamps the peer address per connection, which is what lets a handler make that decision at all. A non-loopback bind with no proxy named warns once at bind, and a pairing call carrying the preshared key on a plaintext client leg warns once per service, while naming a proxy suppresses both. What remains unchangeable at this stage: the daemon cannot detect an operator who exposes the listener without a proxy, a multi-hop forwarded chain is not walked, and a client still has nothing to verify about a proxied endpoint (ADR 0004).

## 2026-10-14, Cancellation and slow-consumer handling (cancellation-and-slow-consumers)

The stream gained an explicit stop and a bound on falling behind. `Cancel` is idempotent and names a request identifier: it answers `CANCELLED` when work was in flight and `ALREADY_FINISHED` otherwise, a cancel under another surface's identifier touches nothing, and dropping a stream still cancels nothing by itself, which is now asserted with a second live stream and the registry's cancellation count. Identifiers travel as `metis-request-id` request metadata and are echoed verbatim in response metadata, so the map's correlation decision landed whole. A consumer that stops reading is no longer served a silent gap: the subscription reports the lag it lost, the serving stream ends with `ResourceExhausted` and a `metis-stream-error: slow-consumer` trailer, and a cancelled stream ends the same way with the `cancelled` value. The wrapper reads that trailing metadata and reports `ClientError::StreamDropped` or `ClientError::StreamCancelled` instead of a transport failure, which closes the map's fog entry about telling a deliberate drop from a transport error; the drop bound is the ring's window and is still not configurable.

## 2026-10-14, Stream resume and expired cursors (stream-resume-and-expiry)

The stream's cursor is now real: `Ring::stream` is fallible at establishment and refuses a cursor the bounded window can no longer serve with `CursorError::Expired`, which crosses the wire as `metis-cursor-error: expired` on a `FailedPrecondition` response and reaches the client as `ClientError::CursorExpired` from the call that opened the stream. A servable cursor replays only the events after it, typed `EVENT` and with no snapshot, so a reconnect carries exactly what the caller missed and nothing twice, while a cursorless stream keeps the landed snapshot shape. A restart expires every cursor, because a fresh ring has no identifier above zero, and the daemon-wide window means a chatty channel can expire a quiet channel's cursor. The resync is the documented cursorless form of the same call with no hidden retry, the proto change is prose only (four comments corrected, no field moved or retyped), and no test pins the wire status code end to end, which is recorded as a residual.

## 2026-10-13, Event stream with snapshot and identifier (event-stream)

`metis.v1` gained its first server-streaming RPC: `StreamEvents` selects channels and carries a `last_event_id` cursor, and every `Event` carries a daemon-wide monotonic identifier, an `EventKind` (the contract's first enum) and a JSON-text payload. `api-contracts::events` holds the bounded ring and one `stream(...)` assembly shared by the daemon and the in-process test service, so every stream opens with a snapshot, then live events, then heartbeats as ordinary messages, and the client drains it through `Client::stream_events`. Authorization now covers streaming as well as unary calls through the interceptor, and this ticket paid three deferred debts: the stream over TCP, the authenticated stream, and the streaming half of the auth interceptor. Resume and expiry, cancellation, and the slow-consumer policy remain with their own tickets, and the payload encoding is JSON text, which is expensive to change under FILE-mode breaking.

## 2026-10-13, Pairing over the remote listener (remote-pairing)

Pairing is now reachable from a device with no local socket: a client pairs over the TCP listener with the preshared key, keeps the minted token, and serves authenticated calls on the same transport. Pairing became optional, since an absent or empty `METIS_PRESHARED_KEY` resolves to `None` and closes pairing while every other call keeps serving, and an unresolvable reference stays a loud error. All three refusal causes, disabled, wrong key and already paired, now travel in a `metis-pair-error` header and reach the client as typed errors instead of `PermissionDenied` or `AlreadyExists`. Closing pairing is a state rather than a revocation, so surfaces paired earlier keep serving until their token row is deleted; the missing rate limit on network-reachable pairing attempts is recorded as fog.

## 2026-10-13, Service-taking TCP front-end (serve-tcp-service)

`transport::serve_tcp_service` and `serve_tcp_listener_service` now mount a `ConnectRpcService` on TCP, the way `serve_uds_service` already did on the Unix socket, because `connectrpc` keeps the interceptor chain on the service rather than the router. Both transports can therefore enforce the credential policy the last ticket added, with no peer-address sniffing: the tests refuse a credentialless call with the typed missing-credential error, serve a paired token, keep `Pair` exempt, and assert the two front-ends answer identically. `serve_tcp_listener` and `serve_stream` were reduced to delegations over the one private connection body, keeping their signatures and observable behaviour, and the workspace suite is at 144 passed, 0 failed.

## 2026-10-13, Pairing, per-surface tokens, and client credential storage (pairing-and-tokens)

`DaemonService` gained `Pair`, gated by a preshared key resolved from a literal, an environment reference, a keystore or a secret file, with a group- or world-readable secret file refused rather than warned about. A successful pairing mints one opaque per-surface token, stores only its SHA-256 in the state database, and returns the text once; the daemon authorizes unary and streaming calls through a `connectrpc::Interceptor` that reads `Authorization: Bearer` and answers `metis-auth-error` with missing, invalid or revoked, while the client keeps its token in the platform keychain through `secret-tool` or `security`, or in a 600 file, and reports which answered. Removing a token row and restarting revokes that surface alone. A listener mounts a `ConnectRpcService` rather than a `Router`, so `serve_uds_service` carries the policy on the Unix socket and the TCP equivalent is the new `serve-tcp-service` ticket.

## 2026-10-13, Daemon state store on SQLite (state-store)

`crates/daemon` now has a library target, and `daemon::state::Store` opens and migrates one SQLite database through sqlx runtime queries: `METIS_STATE_DB` first, then `$XDG_DATA_HOME/metis/metis.db`, then `$HOME/.local/share/metis/metis.db`, with the directory at mode 700 and the file at 600 through the same private-path rule the socket uses. The `tokens` table holds a surface name, the 32-byte SHA-256 of the token's canonical lowercase hex text, and the pairing time, so per-surface revocation is a row delete and the token itself is never stored; `daemon::token` mints and parses it, with the digest pinned by a known-answer test. CI needs no database server, no `DATABASE_URL` and no `.sqlx` offline data, because the store uses runtime queries and embeds its migration.

## 2026-10-13, Local access control and surface identity (local-identity-and-acl)

The daemon now creates its socket directory and the socket itself with mode 700, or 770 when `METIS_SOCKET_GROUP` names a group its user belongs to, and refuses a pre-existing directory that is a symlink, is owned by someone else, or is wider than the rule, instead of chmodding it. Every client call declares `metis-protocol-version`, `metis-surface` and `metis-client-version` as Connect default headers, the service records them, and a missing, malformed or unsupported version is refused with `InvalidArgument` carrying `metis-supported-versions`, which the wrapper turns into `ClientError::ProtocolVersion`; the declaration is not authentication, and credentials arrive with `pairing-and-tokens`. The default endpoint moved off `/tmp/metis-daemon.sock` to `$XDG_RUNTIME_DIR/metis/daemon.sock`, then `$TMPDIR/metis/daemon.sock`, then a typed `NoPrivateBase` error, which closes the conflict between the old `/tmp` default and the ownership rule.

## 2026-10-13, Remote TCP listener, off by default (tcp-listener)

The daemon's service is now reachable over TCP when `METIS_TCP_ADDR` names an `IP:port` literal, and no socket is opened when it does not: there is no default bind address, an absent or empty value disables the listener, and a malformed value is a typed `ConfigError` rather than a silent disable. `transport::serve_tcp_listener` is the one TCP accept loop over the landed `serve_stream`, `serve_tcp` is the bind-and-delegate entry point the daemon will call, `remote_authority` keeps the connection authority and the request authority in step, and `Client::with_remote_addr` reaches the listener without adding a transport injection point to the wrapper. The listener is plaintext and unauthenticated until the TLS, proxy and pairing tickets land, and `serve_tcp` itself has no direct test yet, which the operator accepted as a documented gap.

## 2026-10-13, Plugin version tolerance across compiled versions (plugin-compatibility)

`metis_read_table` now compares `abi_minor` additively with `found >= known`, so a plugin built for a newer minor inside major 1 interoperates while the retired pre-release table at minor 0 is still refused with `MinorMismatch` before any entry is read. A library built for another major fails at symbol resolution with `MajorMismatch` over a real second C library, and the fixture advertises an eighth capability at descriptor version 2, which makes the per-capability gate falsifiable end to end: only that capability is refused and the rest of the plugin keeps serving. Payload types prove that a body carrying an unknown field still decodes, and the harness grew from 62 to 73 checks, including Linux-only faulting-page probes that prove a reader touches only the entries its own `size` covers.

## 2026-10-13, Unify the capability declaration (plugin-contract-v1, amendment)

The declaration both sides of the plugin wire read is now one ungated type in `plugin-contract::capability`, with `serde_json::Value` schemas and a lenient `kind`; `schemars` stays optional behind `authoring`, and the host deleted its own duplicate type and the test that kept the two in step. A capability whose kind this build does not know is refused on its own with `Unsupported` instead of failing the declaration. The wire is byte-identical.

## 2026-10-13, Plugin contract v1: futures-only ABI (plugin-contract-v1)

Futures are now the only way the daemon calls a plugin: `invoke` and the `complete` callback are deleted, `invoke_future`, `service_complete` and `service_request` are the table, and the authoring surface is one capability-name-routed `call` instead of four role-named arms, which removes the four-capability ceiling. The plugin owns no executor and no thread, `async-ffi` is dropped because a destructor panic inside a plugin future aborts the process even for a plugin that returned `Ok`, and unload is quarantine plus one reclaim on a late poll return. `plugin-runtime` gained the loader, the registry, both-direction schema validation and the unload ledger, and a hand-written 482-line C plugin compiles under gcc and clang and is driven end to end by the harness.

## 2026-10-13, Plugin authoring trait and adapters (plugin-authoring-trait)

Plugin authors now write ordinary async Rust: `plugin-contract` gained the feature-gated `authoring` module with the `Plugin` trait, an awaitable cancellation token on the per-request context, the capability declaration, a `const fn` function table, a host adapter, and a minimal executor, while the runtime still depends on the primitives and payload envelope alone. The adapter always completes through the host callback (the ABI keeps its inline path for direct implementers), the trait module names no ABI type, lifecycle hooks and plugin-originated events have routes, and the fixture was rewritten through the trait with the same capability names and single exported symbol.


## 2026-10-13, Local transport and the echo RPC skeleton (local-transport-rpc-skeleton)

Made the first real path between two processes: one handwritten transport module in `api-contracts` that serves any Connect service over a Unix domain socket (and over any async bidirectional stream), plus a UI-independent `client` wrapper that calls the echo RPC without the caller naming a transport, and a runnable example proving it end to end. The endpoint is a platform default with a `METIS_ENDPOINT` override, and the socket tests clean up after themselves. Nothing in the generated trees changed.


## 2026-10-13, Contract gates read one configuration and authenticate to the BSR (contract-gate-hardening)

Moved the buf configuration to the repository root, so `buf lint`, `buf breaking`, and generation read one `buf.yaml` and the declared policy is the one that runs; `--against-config buf.yaml` keeps both sides of the breaking comparison scoped to `contracts/proto`. CI supplies `BUF_TOKEN` from `secrets.BUF_TOKEN` to the single plugin-resolving step and unsets it when the secret is empty, and the gate configuration gained an on-demand acceptance probe at `scripts/probe-contract-gates.sh`. Measured: anonymous resolution is rate limited, an unset or empty token reaches the BSR anonymously, and a non-empty unverifiable token is refused before any request.


## 2026-10-13, Plugin ABI primitives proven by a fixture plugin (plugin-abi-core)

Made the plugin boundary real: `crates/plugin-contract` now holds the `repr(C)` primitive ABI (versioned entry symbol, append-only function table with `size` first, host callback table with `user_data`, status space with `pending`, payload envelope), with the layout asserted in Rust and by a C translation unit compiled on every build. A committed cbindgen header with a drift check, plus a fixture `cdylib` and a 41-check harness that loads it and drives the whole table, including per-side buffer release and panic containment on both sides.


## 2026-10-13, Contract pipeline with one RPC (contract-pipeline)

Made the wire contract real: hand-written Protobuf under package `metis.v1` with
one `Echo` RPC on `DaemonService`, generated by the two pinned BSR remote plugins
into committed Rust in `crates/api-contracts`, mounted with `include!` and the two

plus `buf lint` and `buf breaking` in CI and no JVM, `protoc`, or local plugin
binary. The contract gates and the generated trees now cover the whole workspace
through the existing fmt, clippy, and test steps.
